GitHub Pagesに独自ドメインをつなぐ

Webの接続先とメールの設定を分けて考える。Aレコード、CNAME、HTTPSを確認する手順。

GitHub PagesDNSHTTPS

ドメインと公開先を分けて考える

ドメインの管理会社と、Webサイトを置く場所は同じでなくても構いません。このサイトでは、DNSをValueDomainで管理し、HTMLなどのファイルをGitHub Pagesから配信する構成にしました。

サイトの移転に伴ってメールまで移す必要はありません。変更前のDNSを保存し、Web用のレコードと、メール用のMX・TXTレコードを区別しておきます。

takeshun.net→DNS→GitHub Pages

GitHub側の登録を先に行う

まずGitHubのリポジトリ設定で、PagesのCustom domainにドメインを登録します。その後、DNS側の接続先を変更します。以下は2026年11月2日に公式ドキュメントで確認した設定です。

A  @  185.199.108.153
A  @  185.199.109.153
A  @  185.199.110.153
A  @  185.199.111.153

CNAME  www  grazios.github.io.

これはレコードの種類・名前・値を示した例です。入力形式はDNS管理画面ごとに異なります。既存のWeb用Aレコードを置き換え、メール用のMX・TXTや、関係のないサブドメインは残します。

wwwのCNAMEは、リポジトリ名を含むURLではなく、grazios.github.ioのようなホスト名に向けます。

DNSとHTTPSは別々に確認する

DNSの保存が終わっても、参照するDNSサーバーに古い結果が残っていることがあります。Windowsでは、次のコマンドで接続先を確認できます。

Resolve-DnsName takeshun.net -Type A
Resolve-DnsName www.takeshun.net -Type CNAME
Resolve-DnsName takeshun.net -Type MX

名前解決が正しくなったら、GitHub側の証明書発行を確認します。証明書が利用可能になってからEnforce HTTPSを有効にし、HTTPからHTTPSへの転送も確認します。DNSの反映と証明書の発行には時間差があります。

最後は、実際のURLで確認する

  • 独自ドメインでトップページと記事が開く。
  • CSS・JavaScriptが正しく読み込まれる。
  • HTTPS接続で証明書エラーが出ない。
  • 変更前後でメール用DNSレコードが維持されている。

DNSレコードの確認だけでメールの送受信まで保証できるわけではありません。メール運用に変更を加える場合は、別途送受信も確認します。

今回のメモ

Web公開の変更範囲を小さくし、DNSとHTTPSの完了をそれぞれ確かめる。
